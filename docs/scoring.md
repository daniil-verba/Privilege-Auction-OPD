# Формулы начисления баллов и аукциона

Документ описывает предполагаемую математическую модель начисления баллов за задачи и расчёта начальной стоимости лота на аукционе привилегий.

## Итоговый балл

Итоговый балл за выполненную задачу рассчитывается по формуле:

```
Итоговый балл = Базовая цена + (Бонус × Время × Силы × Коэффициент попыток) − Штраф
```

Где:

- **Базовая цена** — стоимость задачи, которую задаёт администратор.
- **Бонус** — множитель ранга задачи (`M`).
- **Время** — коэффициент скорости выполнения.
- **Силы** — коэффициент сложности задачи.
- **Коэффициент попыток** — множитель, зависящий от количества попыток.
- **Штраф** — штраф за просрочку дедлайна.

## Штраф

Штраф включается только при просрочке дедлайна. Если `Тфакт <= Тплан`, штраф равен нулю. Иначе:

```
Штраф = Базовая цена × min(0.9, sqrt((Тфакт − Тплан) / Тплан))
```

Ограничение `0.9` не позволяет штрафу загнать пользователя в долги и демотивировать его.

Для бытовых задач ранга **D** формула может оказаться слишком жёсткой, поэтому для него используется фиксированный штраф в диапазоне **10–20 %** (например, 15 %).

## Бонус и ранги задач

| Ранг задачи | Примерная базовая цена | Множитель ранга (M) | Описание |
|---|---|---|---|
| D (низший) | до 50 баллов | 1 | Бытовая рутина, мелкие правки, ежедневные привычки |
| C (средний) | 51–200 баллов | 3 | Стандартные рабочие или учебные задачи на пару часов |
| B (высокий) | 201–500 баллов | 5 | Серьёзные задачи, требующие глубокого погружения на весь день |
| A (эпический) | от 501 балла | 10 | Крупные проекты, отчёты, модули, над которыми работают днями |

## Коэффициент времени

```
Время = min(3, Тплан / Тфакт)
```

Ограничение сверху не позволяет бонусу взлететь до небес при мгновенном выполнении задачи.

## Коэффициент попыток

```
Коэффициент попыток = 1 − 0.15 × (Количество попыток − 1)
```

Количество попыток ограничено максимумом **5**, чтобы коэффициент не уходил в отрицательную область.

## Силы

Силы оцениваются по объёму, предполагаемой сложности и возможным рискам или неопределённостям. Каждый параметр оценивается по шкале **1–5**.

У параметров есть весовые коэффициенты, сумма которых должна равняться **1 (100 %)**. Приоритетность может меняться; пример: риски — `0.5`, сложность — `0.3`, объём — `0.2`.

```
Силы = 0.2 × Объём + 0.3 × Сложность + 0.5 × Риски
```

Результат округляется до десятых.

### Критерии оценки «Сил»

| Балл | Техническая сложность (вес 0.3) | Неопределённость и риски (вес 0.5) | Объём работы (вес 0.2) |
|---|---|---|---|
| 1 | Типовая операция: всё делается по готовому шаблону, инструкции или чек-листу. Не требует размышлений | Полная ясность: требования стабильны, подводных камней нет. Результат на 100 % предсказуем | Микро-задача: занимает от 5 до 30 минут. Требует минимум действий (одно-два простых шага) |
| 2 | Базовая задача: знакомый алгоритм. Требуется минимальная адаптация под текущие условия, базовые навыки | Низкий риск: есть лёгкие неточности в ТЗ, но они легко решаются в процессе работы за пару минут | Небольшая задача: занимает от 30 минут до 2 часов. Стандартный рабочий таск средней рутинности |
| 3 | Нетривиальная логика: стандартные подходы, но нужно подумать над архитектурой, связать несколько элементов | Умеренный риск: есть спорные моменты, требующие уточнения у внешних данных или согласования с админом | Средний объём: занимает от 2 до 6 часов (около одного рабочего дня). Требует фокуса и усидчивости |
| 4 | Повышенная сложность: требует глубоких знаний, поиска обходных путей, написания комплексной сквозной логики | Высокий риск: высокая зависимость от внешних факторов (API, третьих лиц). Требования могут измениться на ходу | Большой объём: занимает от 1 до 3 дней работы. Требуется разбиение на подзадачи |
| 5 | Архитектурный вызов: редкие алгоритмы, жёсткая оптимизация, устранение критических багов без документации | Слепая зона: много неизвестных, высокий риск переделок с нуля. Полное отсутствие готовых решений | Эпический объём: крупный проект/модуль, требующий более 3 дней непрерывной работы одного человека |

## Форс-мажор

Пользователь может нажать кнопку «Форс-мажор» и указать причину. Задача отправляется на рассмотрение администратору, который:

- оценивает прогресс выполненной работы в процентах (по четвертям);
- знакомится с причиной форс-мажора;
- принимает одно из решений:
  - заморозить задачу и продлить дедлайн;
  - передать задачу другому исполнителю;
  - отклонить запрос, если считает его попыткой схитрить.

При заморозке время останавливается до возвращения пользователя.

При передаче задачи:

```
Заболевший = Базовая цена × Прогресс %
Новый = Оставшаяся работа % × Итоговый балл × Множитель срочности
```

Множитель срочности по умолчанию — **1.3** (как +30 % к цене).

## Аукцион привилегий

Аукцион онлайн, публичный и английский: сумма ставок возрастает, победитель платит максимальную предложенную им сумму.

Начальная стоимость услуги рассчитывается по формуле:

```
Начальная сумма = Себестоимость × Спрос × Редкость
```

Где:

```
Спрос = min(Число желающих / Число слотов, 3) + 1
Редкость = 1 + 1 / Число слотов
```

- `Спрос` ограничен максимумом `3`, а `+1` не даёт ему стать равным нулю.
- `Редкость` также не позволяет начальной сумме обнулиться.
- Число слотов должно быть не меньше `1`.

Перед аукционом публикуются списки услуг, чтобы участники могли отметить желаемые привилегии. Эти отметки формируют число желающих и используются для анализа спроса.

## Дополнительные механики

### Сгорание баллов

После аукциона **50 % остаточных баллов** сгорает. Это повышает интерес к трате баллов вместо долгого накопления.

### Вклады баллов

Чтобы пользователи могли копить на дорогие привилегии, можно открывать вклады под проценты. Проценты начисляются перед сгоранием и зависят от продуктивности за неделю.

| Результат недели | Условие в программе | Недельный процент по вкладу |
|---|---|---|
| Идеальный (интенсив) | Сдано от 3 задач. Штрафов нет, все задачи с 1–2 попыток | +15 % к сумме вклада |
| Стабильный (норма) | Есть незначительные правки (3+ попытки), но штрафов нет (всё сдано в дедлайн) | +8 % к сумме вклада |
| Спад (прокрастинация) | Была просрочена хотя бы одна задача (начислен хотя бы один штраф) | +2 % к сумме вклада |
| Критический (провал) | Была полностью завалена или брошена задача (5+ неудачных попыток) | 0 % (вклад просто сохраняется) |

## Общий сценарий работы

Администратор создаёт комнату для участников и задаёт ей название. Участники присоединяются по ссылке.

- При личном использовании человек сам назначает себе задачи и предполагаемые награды; возможна функция случайной задачи из накопившихся.
- В командном режиме за задачи и аукцион отвечает создатель комнаты; он видит эффективность каждого участника.
- Задачи начисляются индивидуально. Через «Форс-мажор» задачу можно переназначить лично или выложить в открытый доступ для всех участников.
- У каждого участника есть виртуальный счёт и виш-лист. К напоминаниям можно подключить календарь для планирования задач и контроля дедлайнов.
